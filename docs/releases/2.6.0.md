# bazis-async-request 2.6.0

## Several Kafka topics

A project can route background requests to several topics, e.g. to keep short interactive
requests away from long ones, without its own middleware:

- New setting `BAZIS_ASYNC_REQUEST_TOPIC_RESOLVER` (`BS_BAZIS_ASYNC_REQUEST_TOPIC_RESOLVER`):
  the dotted path of a `callable(payload: AsyncRequestPayload) -> str`. The middleware calls
  it once per request, after the token is checked, and queues the request to the returned
  topic. Unset (the default): `KAFKA_TOPIC_ASYNC_BG`, as before. A resolver that raises or
  returns anything but a non-empty string fails the request and queues nothing. The
  resolver is synchronous and runs in the event loop: no ORM or blocking I/O.
- New module `consumers` with `consumer_for_topic(topic)`: registers a consumer of a topic
  with the logic of `consumer_async_requests` (status, replay marked internal in the ASGI
  scope, stored result). Call it in a module listed in `KAFKA_TASKS`; every topic of the
  resolver needs one. Importing `consumers` registers no subscriber, so a consumer process
  whose `KAFKA_TASKS` lists only the module of a lane serves only its topic;
  `bazis.contrib.async_request.tasks` still registers the consumer of
  `KAFKA_TOPIC_ASYNC_BG` when imported.
- New system check `async_request.E002`: the resolver path does not import (any error of
  the import) or is not callable, so every request sent with `X-Async-Background` would
  fail.

The setting belongs to the package settings: a project that sets `BS_BAZIS_CONFIG_APPS`
(`BS_BAZIS_APPS`) lists `bazis.contrib.async_request` there to use it. See "Several
topics" in `AGENTS.md`.

## Changes

- The code of the consumer moved from `tasks` to `consumers`: `process_async_request`
  (the logic, shared by `consumer_async_requests` and `consumer_for_topic`) and
  `execute_internal_request`. `tasks` re-exports `execute_internal_request`,
  `SKIPPED_HEADERS`, `process_async_request` and `consumer_for_topic`.
- The subscribers are named after the shared function: the FastStream logs and AsyncAPI
  show `ProcessAsyncRequest` instead of `ConsumerAsyncRequests`.

## Tests

- The sample serves a second topic (`fast_start.tasks`, listed in `BS_KAFKA_TASKS`): a test
  routes the update of a shop, allowed only to replayed requests, to it and another request
  to `KAFKA_TOPIC_ASYNC_BG`, and both are executed. Another test imports the modules of
  `KAFKA_TASKS` as a consumer process does: with only `fast_start.tasks` listed, the
  process subscribes only to the topic of the shops.
