# bazis-async-request 2.6.1

## Background requests only for users

`AsyncRequestMiddleware` queues a request with an anonymous token of bazis-ws (16–128
characters `A-Z a-z 0-9 _ -`) to the channel of the token: any client can make up such a
token and put tasks in Kafka. A project whose background requests are only for users had
to replace the middleware to refuse them.

- New setting `BAZIS_ASYNC_REQUEST_ALLOW_ANONYMOUS` (`BS_BAZIS_ASYNC_REQUEST_ALLOW_ANONYMOUS`,
  default `true`, as before). With `false` a request with an anonymous token is answered
  401 (`{"detail": "Background requests require the token of a user."}`) before
  `BAZIS_ASYNC_REQUEST_TOPIC_RESOLVER` is called and nothing is queued. A session JWT is
  checked as before: the token of an active user is queued, an invalid or expired token or
  an inactive user is 401.
- The setting belongs to the package settings: a project that sets `BS_BAZIS_CONFIG_APPS`
  (`BS_BAZIS_APPS`) lists `bazis.contrib.async_request` there to use it, otherwise
  anonymous tokens are queued.
- bazis-ws (already required by bazis-async-background) is a direct dependency: the
  middleware recognizes the anonymous channels by its `ANONYMOUS_CHANNEL_PREFIX`.

## Tests

- With the setting `false` an anonymous token is 401 and neither reaches the resolver nor
  is queued, the JWT of a user is queued, an inactive user is 401; without the setting or
  with `true` an anonymous token is queued to its channel.
