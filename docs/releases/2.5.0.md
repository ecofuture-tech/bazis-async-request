# bazis-async-request 2.5.0

## Breaking changes

- **The 202 answer has one task id.** `{"data": null, "meta": {"async_request_id": <id>}}`:
  the copy `async_background_id` is removed (the client of bazis-front reads
  `async_request_id`). A client that read `meta.async_background_id` reads
  `meta.async_request_id`.

## Changes

- The header `X-Async-Background-Internal` is no longer filtered out of the stored
  requests: since 2.3 nothing trusts it (the consumer marks its requests in the ASGI scope,
  `SCOPE_INTERNAL_KEY`). `X-Async-Background` is dropped once, when the request is stored,
  not again when it is replayed.
- The middleware and `async_request.E001` find the route of the results with one function
  (`utils.results_route_prefix`).

## Tests

- The `test` extra requires bazis-async-background 2.5, whose
  `bazis.contrib.async_background.testing` replaces the copies of the helpers in the
  conftest (`wait_for_task` instead of the fixture `process_async_response`), and
  bazis-test-utils 2.5, whose plugin installs the triggers (also in CI, without
  `pgtrigger install`).
- The test of many patches of an order runs as the support: bazis-permit 2.11 with
  bazis 2.16 refuses the description to the manager of the shop, whose role disables it.
- The Docker Compose stands of the sample (`sample/Dockerfile`,
  `sample/docker-compose.test.yml`, `sample/docker-compose.kafka.yml`, `sample/test.env`)
  are removed: the tests run as in CI, with a Kafka KRaft node (see `CLAUDE.md`).
