# bazis-async-request 2.3.0

Requires Bazis 2.3.1 and bazis-async-background 2.3.

## Security

- **`require_async` could be bypassed** with the header `X-Async-Background-Internal: true`,
  which the consumer added to the replayed requests and which any client could send. The
  consumer now marks its requests in the ASGI scope (`SCOPE_INTERNAL_KEY`), which clients
  cannot set; the header is ignored (and removed from stored requests).
- In the sample project `require_async` was declared without a type annotation
  (`_async_request = Depends(...)`), so the dataclass of `inject_make` ignored it and the
  update of a shop was not limited at all. Dependencies of `inject_make` classes must be
  annotated (`async_request: None = Depends(require_async)`); the README is fixed.
- A failed request stores a generic error instead of the exception text.
- Anonymous clients use the channels of bazis-ws 2.3 (see bazis-async-background 2.3).

## Fixes

- **Consumers did not start with current FastStream** (`auto_commit` was removed): the
  subscriber uses `subscriber_kwargs()` of bazis-async-background.
- The replayed request kept the `Content-Length` of the original request with a re-encoded
  body, got a percent-decoded `path`,
  the ASGI version, `root_path` and lifespan `state`; `receive` no longer returns the
  request again in a loop (streaming responses spun the CPU).
- `class Config` (Pydantic v1 style, deprecated) of the payload schema is replaced with
  `model_config`.

## Documentation

- The README named the header `X-Async-Request` and the module `dependencies`; they are
  `X-Async-Background` and `utils`. It also described an anonymous channel name header that
  does not exist: anonymous clients send their own token as `Authorization: Bearer`.
- The stored requests contain all headers, `Authorization` included.

## Tests

The tests no longer require Docker: they skip the consumer tests without Kafka settings,
wait for the tasks of a test before the database is flushed (the consumer shares it), and
compare responses without the parts that depend on middleware versions (`Vary`, content
length) and on `DEBUG` (tracebacks). The `test` extra installs the packages the sample
project uses. CI starts Kafka (KRaft) and a consumer and runs all tests on Python 3.12–3.14
and with the lowest allowed dependency versions; releases are made with the Release
workflow (see `CLAUDE.md`).
